Estado de las demosDemo status

Si cada demo del portafolio responde, cuánto tarda y cuántas veces falló en las últimas 24 horas y 7 días. Whether each portfolio demo responds, how long it takes, and how often it failed in the last 24 hours and 7 days.

Cómo funcionaHow it works

  1. Cada 15 minutos, una función AWS Lambda hace una petición GET a cada demo y anota el código HTTP y el tiempo de respuesta.Every 15 minutes, an AWS Lambda function sends a GET request to each demo and records the HTTP status code and the response time.
  2. Publica el resultado, con el historial de los últimos 7 días, en /data/estado.json; esta página solo lee ese archivo.It publishes the result, with the last 7 days of history, to /data/estado.json; this page only reads that file.
  3. Mientras la tienes abierta, esta página vuelve a leer el archivo cada 5 minutos. Si el último chequeo tiene más de 45 minutos, muestra un aviso.While you have it open, this page reads the file again every 5 minutes. If the latest check is more than 45 minutes old, it shows a warning.
  4. Si una demo falla dos chequeos seguidos, la portada, y el laboratorio de esa demo si lo tiene, cambian su botón por un enlace a esta página. Si el archivo está desactualizado, no se oculta nada.If a demo fails two checks in a row, the home page, and that demo’s lab if it has one, swap its button for a link to this page. If the file is stale, nothing is hidden.

Un chequeo es correcto cuando la demo responde con el código esperado (200) antes de 20 s. La latencia es el tiempo hasta recibir los primeros 2 KB; la mediana y el p95 usan solo los chequeos correctos (percentil por rango más cercano). Las ventanas de 24 h y 7 días se cuentan hacia atrás desde el último chequeo. A check passes when the demo answers with the expected status code (200) within 20 s. Latency is the time to receive the first 2 KB; the median and p95 use passing checks only (nearest-rank percentile). The 24 h and 7-day windows count back from the latest check.
